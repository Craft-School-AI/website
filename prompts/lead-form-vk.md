# Промпт: форма заявок → ВКонтакте

Тема занятия — **сбор заявок**. На выходе: рабочая форма на сайте, которая
отправляет заявку вам в личные сообщения ВКонтакте.

## Как это работает (коротко)

Посетитель заполняет форму → сайт отправляет данные **на свой сервер** (не сразу
во ВК) → сервер делает запрос к **API ВКонтакте** и присылает вам сообщение.

Почему через свой сервер, а не напрямую из браузера: для отправки нужен
**секретный токен ВК**. Если положить его в код страницы, его увидит любой
посетитель и сможет писать от вашего имени. Поэтому токен живёт **только на
сервере**, в переменных окружения, и в браузер никогда не попадает.

## Что подготовить заранее (5 минут)

1. **Токен ВК.** Сообщество ВК → Управление → Работа с API → создать ключ
   доступа с правом «Сообщения сообщества». Это и есть `VK_ACCESS_TOKEN`.
2. **Кому слать (`VK_PEER_ID`).** Проще всего — id вашего личного профиля ВК
   (число). Сообщество должно иметь право писать вам, или используйте peer_id
   беседы/сообщества. На занятии подскажем, как получить.
3. **Файл `.env.local`** в корне проекта (агент создаст, вы впишете значения):
   ```
   VK_ACCESS_TOKEN=ваш_секретный_токен
   VK_PEER_ID=ваш_id
   VK_API_VERSION=5.199
   ```
4. Убедитесь, что `.env.local` **в `.gitignore`** — ключи не коммитим.
   На проде (Timeweb) те же переменные добавляются в настройках окружения, а не в код.

## ▼▼▼ ВСТАВЬТЕ ЭТО АГЕНТУ ▼▼▼

Добавь на мой сайт (Next.js, App Router) рабочую форму заявок, которая
отправляет заявку мне в личные сообщения ВКонтакте. Требования:

**Форма (клиентский компонент):**
- Поля: имя (обязательно), способ связи — телефон или ссылка на соцсеть
  (обязательно), комментарий (необязательно).
- Состояния кнопки: обычное, «Отправляем…» (заблокирована во время запроса),
  успех («Спасибо, заявка отправлена»), ошибка с понятным текстом.
- Простая валидация на клиенте (имя ≥ 2 символов, контакт заполнен).
- После успешной отправки — очистить форму и показать сообщение об успехе.
- Отправляй данные `fetch('/api/lead', { method: 'POST', body: JSON })`.

**Серверный роут `app/api/lead/route.ts` (это важно — здесь секрет):**
- Обрабатывает `POST`, читает JSON, валидирует поля ещё раз на сервере.
- Секреты берёт ТОЛЬКО из переменных окружения:
  `process.env.VK_ACCESS_TOKEN`, `process.env.VK_PEER_ID`,
  `process.env.VK_API_VERSION` (по умолчанию `5.199`).
- Никогда не пиши токен в код и не отдавай его в браузер.
- Собирает читаемый текст заявки (имя, контакт, комментарий) и отправляет
  запрос к API ВКонтакте:
  `POST https://api.vk.com/method/messages.send`,
  `Content-Type: application/x-www-form-urlencoded`,
  параметры: `access_token`, `peer_id`, `message`, `v` и обязательный
  `random_id` (например, timestamp + случайное число — ВК использует его,
  чтобы не задваивать сообщения).
- Учти: **ВК отвечает HTTP 200 даже при ошибке** — реальная ошибка лежит в теле
  ответа в поле `error`. Проверяй и `response.ok`, и `data.error`.
- Если переменные окружения не заданы — не падай: залогируй на сервере и верни
  понятную ошибку («Форма временно недоступна»).
- Возвращай `{ ok: true }` при успехе и `{ ok: false, error }` при ошибке,
  с корректными HTTP-статусами (400 — неверные данные, 502/503 — проблемы отправки).

**Безопасность:**
- Токен и peer_id — только в `.env.local` (создай файл-пример `.env.example`
  без реальных значений). Убедись, что `.env*` в `.gitignore`.
- Не логируй сам токен. В логи можно писать текст заявки, но не секреты.

Разбей код на компоненты, объясни простыми словами, что делает серверный роут,
и как проверить, что заявка дошла.

## ▲▲▲ КОНЕЦ ПРОМПТА ▲▲▲

## Как проверить

1. Впишите значения в `.env.local`, перезапустите dev-сервер.
2. Заполните форму на сайте и отправьте.
3. Проверьте личные сообщения ВК — должна прийти заявка.
4. Если не пришла — смотрите логи сервера: там будет причина (неверный токен,
   нет прав «Сообщения сообщества», неверный peer_id).
